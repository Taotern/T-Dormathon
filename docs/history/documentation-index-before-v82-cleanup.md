## Frontend and prototype intent · 前端与原型意图

The user and assistant own the complete frontend and later visual styling. The product must be eye-catching as well as simple, direct and complete. Subsequent Xushi Deconstruction styling uses black, white and gray, strong composition, layers, data emphasis and appropriate motion; both appeal and usability matter. Teammates' current assignments cover backend functionality, contracts and runnable examples, without visual-design acceptance obligations. The canceled super-frontend and slide-style presentation remain canceled.

整体前端及后续视觉装修由用户与助手负责。产品既要抓眼，也要简洁直接地完整展示；虚实解构的黑白灰、强构图、层次、数据重点和适当动效须同时服务吸引力与可用性。队友当前只交付后端功能、契约和可运行示例，不承担视觉验收。已取消的超前端和 PPT 式展示不恢复。

A minimum backend accelerates a complete usable prototype; it must not produce a weak prototype. The experience aims to connect global data, risk discovery and preventive recommendations, sandbox simulation and Agent consultation. Existing coverage and capabilities remain tied to actual acceptance. “Self-improvement” requires feedback, version and evaluation evidence before being claimed.

最小后端用于加快完整可用原型交付，不能因此做出薄弱原型。整体体验目标串联全球数据、风险发现与预防建议、沙盘推演和 Agent 咨询；现有覆盖和能力仍以实际验收为准。“自我改进”须有反馈、版本和评估证据后才作为能力声明。
